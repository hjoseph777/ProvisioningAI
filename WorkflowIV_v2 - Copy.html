1. Every terminal branch cross-vault-moves

Approval, Statement, OtherDoc, PackingSlip AND Trash each bind their own Vault Toolbox action that moves the object into Approbation under a distinct class. No purely-local terminal outcome exists except the final Delete after a successful Trash move — the handoff blocker affects every scenario, not just the happy path.

2. Only MoveToApproval sets a destination workflow

MoveToApproval carries 5 destination GUIDs (incl. Workflow + WorkflowState — the entry point). MoveToStatement, MoveToOtherDoc, MoveToPackingSLip and 'To trash' carry only 3 — no destination workflow placement.

3. WAIT_SQL_RETRY loop — confirmed, not a concern

WORKFLOW_ERREUR → WAIT_SQL_RETRY and back to UPD_VendorID/UPD_SQL_CP1 carry a decoded VBScript timer guard (~1 minute since Created) — a genuine automatic retry. Property Calculator could not replace this: it cannot make external SQL calls, which is the whole point of the retried operation.

4. RTE_Missing Value bypasses everything

State 116 skips BOTH the credit-check cascade and the entire duplicate-check cluster en route to Control Invoices. An invoice can reach Approbation without FindDuplicates ever running. Confirm intentional with Philippe.

5. SET_CREDIT_NEGATIF is not terminal

A sign-flip step that always loops back through the duplicate-check cluster and a second Control Invoices classification pass (scenarios #8/#9).

6. Deliberate simplification

The SQL/CP1 vendor-learning-export sub-chain (120/121 → 151 → 152 → 142 → 136 → 144 → 145 → 205 → 195 → 196 → 134) is treated as shared plumbing inside the #1/#2/#8/#9 backbone rather than its own scenario. Not independently live-traced.

1) Control Invoices (119) — CONFIRMED MANUAL HUB

State 119 carries zero logic: both VBScript and property preconditions disabled; actions limited to a plain SetProperties. Nothing to attach a marker to — matching the diagram, where indicators sit on arrows, not the box.

9 of 10 outgoing edges are structurally empty on all three guard fields (triggerMode 0, triggerCriteria null, triggerAllowedByVBScript blank): to 126, 139, 140, 124, 155, 202, 203, 134, 219. A human operator selects the destination.

Exactly one exception: 119 → RTE_CP1 (125), transition ID 83 — triggerMode 4 with a real 618-char opaque encoded condition (not VBScript). This is the only automated edge out of the hub, and it is still undecoded. OPEN

Nuance: the human's choice is validated downstream, not at 119. Destination states 202/124/203 carry real VBScript field-completeness preconditions; 139/140 carry their own opaque property preconditions. Those live on the destination's entry, not the transition.

2) Alias-derivation pattern (methodology)

Squash rule: WFS.<Workflow>.<Alias> = state Name with spaces/underscores/hyphens/plus stripped, first char kept, rest lowercased. Confirmed on 11 pairs. Not universal — 'ToTrash' and 'Bratravendor' do not fit cleanly; flagged as ambiguous rather than silently corrected.

3) Intake-landing quirk — real M-Files engine behaviour

Objects created at 115/143 auto-cascade through unconditional transitions within the same check-in until reaching a state that needs human action, a real guard, or an async task result. Confirmed NOT a harness artifact and NOT an add-on redirect.

4) Local Trash reclassification NEW

ConformityVaultApplication reclassifies the LOCAL object to CL.Trash on entry to all three of Statement(139)/OtherDoc(140)/PackingSlip(203) — the same treatment as Trash(141) itself. Conformity keeps its own copy filed as Trash while the true, properly-classed object ships to Approbation.

5) Credit-note sign-flip precision

Property Calculator's 'Invoices (Crédit en Négatif)' class has 5 separate per-field rules, each gated on State=SET_CREDIT_NEGATIF AND field > 0.00 — a field already zero or negative is left untouched, preventing a double-flip if the workflow loops twice.

6) Naming history

CP1 is the original name for what is now UPD_Learning — an external OCR/vision call. The CP1 naming persists throughout the workflow, the SQL tables (Master_DATA_CP1) and the export paths.
